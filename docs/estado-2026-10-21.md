### 1. Verificar si la migración está aplicada

En el SQL Editor de Supabase:

```sql
select proname, prosecdef as security_definer
from pg_proc
where pronamespace = 'public'::regnamespace
  and proname in (
    'acreditar_interes_cuentas', 'preparar_reserva', 'mover_reserva', 'comprar_mercado',
    'solicitar_prestamo', 'cobrar_cuotas_prestamos', 'alta_cliente', 'marcar_situacion_informada',
    'abrir_cuenta_usd', 'acreditar_transferencia_entrante', 'depositar_en_cuenta'
  )
order by proname;
```

- **11 filas, todas con `security_definer = true`:** la migración está aplicada. Pasar al punto 3.
- **Faltan filas, o `depositar_en_cuenta` figura con `false`:** no está aplicada. Seguir con el punto 2.

### 2. Aplicar la migración (manual §7.7, pasos 1 y 2)

1. **Comprobar que las políticas coinciden con las del repo** (`policies.sql`, `reservas.sql`, `prestamos.sql`):

   ```sql
   select tablename, policyname, cmd from pg_policies
   where tablename in ('cuentas','personas','movimientos','reservas','prestamos')
   order by tablename, cmd;
   ```

2. **Aplicar `supabase/s1_rpc_saldos.sql`** completo en el SQL Editor. Es aditivo: no le quita nada a la app.
3. **Repetir la consulta del punto 1** y confirmar que devuelve las 11 filas.

### 3. Desplegar la Edge Function (manual §7.7, paso 3)

```bash
npx supabase login
npx supabase secrets set BC_API_KEY=<la misma key que VITE_BC_API_KEY> --project-ref <ref>
npx supabase functions deploy sincronizar-entrantes --project-ref <ref>
npx supabase functions list --project-ref <ref>   # tiene que aparecer sincronizar-entrantes
```

- **`BC_API_KEY`:** obligatorio. Sin él, la función responde error 500.
- **`BC_URL`:** opcional. Por defecto apunta a `https://centralbank.brocoly.cc/api`.
- **JWT:** la función va **con** verificación de JWT (sin `--no-verify-jwt`), porque la llama el usuario logueado.

### 4. Probar en producción

Recorrer el checklist de `manual-despliegue.md` §13. Prioridad: registrarse, ingresar y retirar de una reserva, una compra en mercadoMONIX, pedir un préstamo y recibir una transferencia desde otro banco.

### 5. Todavía NO: revocar escrituras

`supabase/s1_revocar_escrituras.sql` (manual §7.7, paso 5) va **sólo** después de que el punto 4 salga bien. Es el paso que cierra la vulnerabilidad: hasta aplicarlo, un usuario logueado todavía puede escribir su propio saldo desde la consola del navegador (V2 en la auditoría).

Después de aplicarlo, probar desde la consola del navegador con una sesión iniciada. Tiene que devolver un error de permisos:

```js
await supabase.from('cuentas').update({ saldo: 1 }).eq('id', '<id de una cuenta propia>')
```

Cuando esté hecho, actualizar la fila S-1 de la tabla "Plan y estado" en `auditoria-2026-10.md`.
